## Відкриті задачі

1. NovaPay API:
   - додати налаштування NovaPay у `Налаштування -> Обмін даними`;
   - додати серверний шлюз для NovaPay, який підписує запити приватним ключем;
   - додати у mock/API endpoint для тестового отримання платежів;
   - додати у CRM блок `Фінанси -> Оплати` для імпорту платежів NovaPay;
   - звіряти оплату по ТТН із замовленням;
   - створювати оплату в CRM;
   - переводити замовлення у статус `Оплачено`, якщо сума відповідає;
   - показувати помилки з кодами.

2. Коди помилок для NovaPay, які треба використати:
   - `NPAY_EMPTY_TTN` - у платежі немає ТТН;
   - `NPAY_NO_ORDER_BY_TTN` - у CRM не знайдено замовлення з такою ТТН;
   - `NPAY_AMOUNT_MISMATCH` - сума платежу не збігається із сумою замовлення;
   - `NPAY_GATEWAY_ERROR` - серверний шлюз NovaPay не відповів або повернув помилку;
   - `NPAY_SIGNATURE_ERROR` - помилка підпису запиту на шлюзі;
   - `NPAY_IMPORT_PARSE_ERROR` - не вдалося розібрати JSON відповіді.

3. Підключення CRM до SQL:
   - CRM має отримувати з PostgreSQL товари, залишки, клієнтів, дебіторку, склади, фірми;
   - на старті тільки read-only отримання з SQL;
   - не писати назад у 1C;
   - перевірити, що клієнти з маркетплейсів додаються у `Продажі -> Клієнти` з колонкою джерела.

4. Товари / склад / логістика:
   - винести склад і логістику окремими блоками під `Продажі`;
   - додати підтвердження відбірки завскладом;
   - додати передачу на доставку;
   - додати підтвердження логістом;
   - додати відстеження ТТН через API Нової Пошти та Укрпошти;
   - додати API налаштування служб доставки.

5. Ролі:
   - перевірити, що всі нові блоки є у ролях;
   - додати права для NovaPay API;
   - додати права для рознесення оплат;
   - додати права для складу, логістики, підтвердження відбірки, передачі на доставку.

6. Логи:
   - кожна вдала дія має записуватися в лог;
   - кожна провальна дія має записуватися в лог з кодом помилки;
   - лог має містити дату, що змінювалось, які файли, результат перевірки.

## Помилки

Відомі помилки і ризики:

- `192.168.4.14:8789` у браузері показує `ERR_CONNECTION_TIMED_OUT`; сервер прототипу треба запустити або перевірити доступ по LAN/фаєрволу.
- Перевірка `git status --short` у `D:\Codex\CRM\marketplace-crm` завершилась помилкою:
  - код: `git-dubious-ownership`;
  - текст: `fatal: detected dubious ownership in repository at 'D:/Codex/CRM/marketplace-crm'`;
  - причина: репозиторій належить `ZAKHP/CodexSandboxOffline`, а поточний користувач `ZAKHP/User`.
- Старі файли логів частково відображаються з mojibake у PowerShell через кодування консолі. Самі файли треба відкривати в редакторі з UTF-8 або перевіряти кодування перед масовими правками.
- Не можна перезавантажувати робочий 1C-сервер без узгодження.
- Не можна тримати приватний ключ NovaPay у `app.js`, `index.html`, localStorage або в браузері.
- PowerShell mock/API сервер може не стартувати, якщо порт `8789` уже зайнятий.

## Наступні кроки

Почати з безпечної реалізації NovaPay у прототипі:

1. Відкрити `D:\Codex\CRM\marketplace-crm\app.js`.
2. Додати в seed state:
   - `settings.novaPay`;
   - `novaPayTransactions`.
3. Додати права:
   - `novaPayApi`;
   - `novaPayReconciliation`;
   - field lock `novaPay`.
4. Додати UI:
   - `Налаштування -> Обмін даними -> NovaPay API-шлюз`;
   - `Фінанси -> Оплати -> NovaPay: рознесення оплат по ТТН`.
5. Додати логіку:
   - імпорт платежів NovaPay з JSON;
   - отримання платежів із gateway endpoint;
   - пошук замовлення по ТТН;
   - перевірка суми;
   - створення оплати;
   - оновлення статусу замовлення.
6. Додати mock endpoint у `D:\Codex\CRM\marketplace-crm\mock-api.ps1`:
   - `GET /api/novapay/payments`
7. Оновити версію:
   - `APP_VERSION` у `app.js`;
   - script query у `index.html`;
   - блок версії у лівому меню.
8. Перевірити:
   - `node --check app.js`;
   - синтаксис `mock-api.ps1`;
   - запуск mock/API сервера;
   - відкриття `http://127.0.0.1:8789/index.html`;
   - відображення блоків NovaPay;
   - тестове рознесення платежу по ТТН.
9. Усі результати записати в:
   - `D:\Codex\CRM\SQL\docs\crm-sql-work-log-2026-06-01.md`
